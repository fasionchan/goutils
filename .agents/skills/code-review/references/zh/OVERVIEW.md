# 总览：范围、非范围与严重度

## 范围（首版强制）

对 Go 源码（或以其为主的变更）按通用框架审查：

- 命名与风格
- 错误处理
- 包 / API 与导出惯例
- 并发与 `context`（若适用）
- 测试与可维护性
- 轻量安全常见坑（常见误用清单，**非**完整安全评估）

## 非范围（首版不强制）

以下**不在**首版强制范围；评审输出须在「未覆盖 / 超出范围」中显式声明未做：

- 完整安全审计 / 渗透测试方法论
- 性能 profiling 与系统性性能优化证明
- 业务正确性证明（需求是否被完整实现）
- 非 Go 语言评审
- CI / `golangci-lint` 流水线改造
- 项目个性化细则（见扩展位；为空则不编造）

## 严重度定义

| 级别 | 含义 |
|------|------|
| `blocker` | 必须改，否则不应合并（正确性/安全硬伤、明显破坏 API 契约） |
| `major` | 强烈建议改（错误处理缺失、明显风格违规致可维护性风险） |
| `minor` | 建议改（局部风格/命名不一致） |
| `nit` | 可选润色（口味级） |

输出时按 `blocker` → `major` → `minor` → `nit` 分组；无问题的级别写「无」。

## 扩展位

`project-specific/` 用于后续追加项目个性化原则。首版仅占位：加载通用章后，若扩展位无实质内容则跳过。
