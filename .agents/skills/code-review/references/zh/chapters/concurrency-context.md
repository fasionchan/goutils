# 并发与上下文

通用 Go 并发与 `context` 检查项（无并发代码时可标注「不适用」并跳过细项）。

## 检查项

1. **跨 API 边界传递 `context.Context`**：可能阻塞、IO、RPC 或长循环的函数应将 `ctx` 作为首参；禁止在库代码中擅自用 `context.Background()` 吞掉上游取消信号（入口/main 除外）。
2. **防止 goroutine 泄漏**：每个启动的 goroutine 须有退出条件（`ctx.Done()`、channel 关闭等）；审查是否存在无人接收的发送或永不退出的循环。
3. **channel 与锁的所有权清晰**：明确谁发送、谁关闭；避免在多个生产者上关闭同一 channel；共享状态用 mutex 或 channel 之一保护，勿数据竞争。
4. **不要在持锁时做不可控阻塞**：持有锁期间避免网络 IO、无界 channel 操作或调用可能再获取同锁的代码，以防死锁。
5. **竞态与生命周期文档化**：对「先关闭再读」「WaitGroup 加减不匹配」等高风险模式重点核对；并发原语的生命周期应在注释或 API 文档中可理解。
