# 包、API 与导出惯例

通用 Go 包结构与导出 API 检查项。

## 检查项

1. **最小化导出面**：仅导出调用方确实需要的类型、函数与字段；包内实现细节保持未导出，避免泄漏可破坏的内部状态。
2. **API 命名体现包路径语义**：函数名不要重复包名（优先 `http.Get` 而非 `http.HTTPGet`）；构造器惯用 `New` / `NewXxx`。
3. **接口由消费方定义、保持小而稳**：避免过早导出巨大接口；接受接口、返回具体类型是常见偏好（按场景权衡），接口变更须评估兼容性。
4. **零值可用性与配置默认值**：类型在合理范围内应零值可用来用，或提供清晰的 `New` 初始化；导出配置字段的默认值与合法性须可文档化。
5. **避免循环依赖与杂乱包边界**：包应按职责分层，禁止为图省事把无关工具塞进高扇出包；新增依赖方向应单向、可解释。
