# 测试与可维护性

通用 Go 测试与可维护性检查项。

## 检查项

1. **导出行为应有对应测试或可说明的免测理由**：新增/变更的公共逻辑应有单测或集成测覆盖主路径与关键错误路径；若故意不测，须说明原因。
2. **测试应可重复、无外部脆依赖**：默认单测不依赖真实网络/时钟/随机顺序；需要时用接口注入、fake 或明确的 integration 标签隔离。
3. **表驱动测试与失败信息可读**：多分支优先表驱动；失败时输出输入与期望/实际，避免只写 `t.Fatal("failed")`。
4. **函数保持单一职责、控制复杂度**：过长函数、深层嵌套或隐式全局依赖应拆分为可测小函数；魔法数提取为命名常量。
5. **注释解释「为什么」而非复述代码**：导出符号的 Go doc 完整；删除过时注释与死代码，避免误导后续维护者。
